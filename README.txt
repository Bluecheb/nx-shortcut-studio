NX Shortcut Studio (local)

Double-click "Open NX Shortcut Studio.cmd". The site opens directly in your browser and does not need a server or an open command window. If your browser restricts direct local files, use "Launch NX Shortcut Studio.cmd" instead and keep its command window open.

Press keys while the site tab is focused to see them light up and read the assigned NX command. You can drag an assigned key onto another key to move it or swap their commands. The categorized NX command library searches 2,531 command codes taken from the installed NX 2606 menu files. Click a result to add it, then click its assignment to record a shortcut. If the shortcut belongs to another command, a popup offers to swap the two shortcuts. Your edits save in this browser.

When you click + Add in the command library, the site switches to the selected Modeling or Sketching keyboard and immediately records the next key or key combination you press. You do not need to click the new assignment first.

Mouse Controls plans assignments for mouse buttons and wheel gestures. Circular Menus provides three eight-position radial layouts. These sections are included in the JSON layout export. Their NX role targets have not yet been verified, so they are not written into the MTX.

Visible NX Tabs controls supported existing top ribbon and sidebar states from your uploaded baseline. Choose Modeling, Sketching, or No Part. Docked ribbon records use their nested stack visibility; detached/full-screen records remain unsupported. Sidebar edits use exact existing application states. Docking, size, order, inherited states and touch settings remain unchanged. Choices save in the browser and are reviewed before MTX export.

"What are you using NX for?" autofills suggested ribbon/sidebar visibility in all three workspaces. Presets do not supply or change shortcuts. Hidden tabs can be enabled later. CAM preparation is a suggestion for these workspaces, not a Manufacturing-application ribbon configuration.

Merge .mtx Roles transfers matching ribbon/sidebar visibility only into the chosen base. Shortcuts, command definitions, tab order, docking, and unrelated preferences stay from the base. Missing/unsupported targets are reported and block merge export. Export makes a separate MTX without modifying uploaded files. Use roles from the same NX version; custom tabs require their original definitions/add-ins. Native NX validation is still required.

Create Reference Geometry is not a stock bindable NX command. The included journals\ToggleCreateReferenceGeometry.vb file flips NXOpen.Preferences.SessionSketch.CreateReferenceGeometry and reports whether it is ON or OFF. Test it through Tools > Journal > Play. To give it a shortcut, register it as a user-defined NX command, paste the actual command ID generated by NX into the Studio, and add it to Sketching shortcuts. See journals\README.txt. The suggested command ID is a placeholder until NX registers it.

Export layout is the legacy JSON format and may include your personal journal IDs. Review & export .mtx requires a role uploaded from your own NX setup, then shows the exact supported changes. No-edit downloads return the original text. Shortcut mutations require existing edit-mode containers; command-definition-only roles can still export unchanged or with tab-only edits. Keep your baseline, finish the active sketch, save your parts, load outside Sketch, restart NX, and verify shortcuts, tabs and dimension behavior. Native NX 2606 checks passed for the tested docked layout, shortcut persistence, and original-role restoration; verify your own setup too.

Roles with separate create/edit sections are supported conservatively: command
definitions stay untouched and shortcut edits use only the existing edit section.
Stored tab visibility does not guarantee availability in every NX application.

The command catalog records whether NX declares each action as a normal button, toggle, or application action. MTX export preserves that action type; this is required for commands such as Sectioning Toggle and Quick Trim. Construction Lines creates derived construction-line geometry; it does not toggle the Create Reference Geometry preference.

NX's standard icons are packed in .bma archives. The site does not display those icons yet; it uses command names and codes. The right-click wheel is unchanged. Caps Lock as Enter and Maya-style mouse navigation are separate from an NX keyboard role.

The browser can detect keys only while this tab is focused, not while NX is focused.

Journal Commands on Your Keyboard lets you set a readable name, paste the actual
NX user-button command ID, and choose Sketching or Modeling/general. Add the command
and record a shortcut. Existing journal assignments have an Edit Journal Name /
Command ID control; saving an ID preserves its shortcut. JSON retains journal
metadata. MTX writes the exact configured ID and blocks the old placeholder ID.
The command ID field starts blank; each user must supply their own NX button ID.
A role accelerator does not install the custom button
or journal. Keep those installed in NX, and preserve their definitions in your role.

Overlay Buddy Web Prototype shows the exact selected Ctrl/Alt/Shift combination
for Modeling or Sketching. It is browser-only, not a desktop overlay or keyboard
hook. It does not run commands. Download portable project saves a version 1
.nxstudio.json file with journal slots instead of personal IDs, portable tab
choices, and display settings. Imported files are reviewed before applying
built-in shortcuts or matching tab choices; local journal bindings are retained
and conflicts block import. Foreign journal assignments remain preview-only.
See PORTABLE_PROJECT_FORMAT.md. Other user-authored labels remain visible, so
review the JSON before public sharing. No role, session state, or file-backed
palette path is included in the portable format. The desktop Overlay Buddy is
not yet built; only the browser preview and separate pure display controller
are implemented. See companion/README.md and ROLE_EXPORT_RELEASE_NOTES.md.
